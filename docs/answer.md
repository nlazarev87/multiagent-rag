# Ответ

Код: `answer_agent` и соседние функции в [src/agents.py](../src/agents.py). Модель вызывает [src/llm.py](../src/llm.py).

Собирает текст ответа по уже найденным чанкам. Проверка ещё впереди: здесь ответ можно вернуть без модели, если чанки сами содержат нужную строку.

## Вход и выход

`answer_agent(query, clear_query, chunks, work_turns, feedback=None)`. Пустые чанки дают «В документах нет ответа.» Иначе порядок такой:

1. Латинский токен, которого нет в текущих чанках, ищется в остальных чанках уже выбранных документов и ставится первым.
2. Для «что такое» вперёд ставится секция с «наименован» или «характеристик», где есть сам термин. Чанк протокола, где термин только в роли отправителя или получателя, убирается.
3. Без отзыва проверки вопрос со списком или числом может закрыться строкой обзора таблицы, без вызова модели.
4. Иначе модель получает промпт и примеры из `data/prompts/`. Повторная ссылка на тот же номер в хвосте снимается.

## Инварианты

- Обзор «Разных значений в столбце «X»: N. Список: …» для вопроса «сколько» отвечает фразой «N {подпись столбца} [n]», а не отказом из-за другого заголовка, который совпал сильнее.
- Латинское покрытие не открывает новый документ. Оно читает только файлы, которые поиск уже выбрал.
- Обзор не подменяет ответ, если это повтор после отзыва `check`. Иначе проверка не может заставить модель переписать текст.
- Оборванный ответ, который кончается на «:», «следующие» или «следующее», здесь не лечится. Его отклоняет проверка, см. [check.md](check.md).

## Настройки

`data/prompts/answer.json` — системный текст, лимит `prompt_tokens`, фразы отзыва. `data/prompts/fewshot.json` — примеры. Примеры остаются: проверка отдельно ловит длинные слова, заимствованные из них.
