# Настройки и тексты для модели

Код: [src/settings.py](../src/settings.py).

Читает JSON и держит его в памяти процесса. `reload()` заставляет прочитать файлы заново. Пути можно подменить переменными `APP_ROOT`, `CONFIG_DIR`, `PROMPTS_DIR`. Так тесты не трогают рабочие файлы.

## Файлы

- `config/runtime.json` — размеры поиска и куска текста, `attempts`, `n_ctx`, `max_tokens`, `temperature`, `prompt_tokens`, `span`, `search_limit`.
- `config/routing.json` — когда отвечать списком файлов, слова `catalog_skip` и необязательный фильтр `where`. Слишком широкий шаблон уводит обычный вопрос в список файлов. `catalog_skip` не даёт словам самого вопроса выкинуть файлы из этого списка.
- `config/check_lexicon.json` — начала слов для единиц, размеров и отклонений. Это не список документов.
- `data/prompts/answer.json` — роли и фразы отзыва для ответа и проверки.
- `data/prompts/fewshot.json` — примеры вопрос, фрагменты, ответ. Их видит и модель, и проверка чужих слов.

## Что нельзя сломать

- Факт из конкретных документов кладётся сюда или в тест, не в `src/`.
- `where()` выбрасывает пустые значения фильтра, чтобы они не становились условием поиска.
- После правки этих файлов заново измерить то поведение, которое сдвинулось. Если менялись маршруты или знание о документах, прогнать `tests/test_universality.py` и `tests/test_guard.py`.

## Проверка

Имена проверок: утечка знаний в код должна быть 0 (`code_knowledge_leakage`), подмена документа должна проходить (`document_swap_pass_rate` = 1), ссылки должны покрывать ответ, смена только настройки должна удаваться.
