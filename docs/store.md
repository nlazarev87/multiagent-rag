# Индекс и поиск

Код: [src/store.py](../src/store.py). Из цепочки вопроса его вызывает `search_agent` в [src/agents.py](../src/agents.py).

Хранит куски текста и ищет по ним. Один список строится по смыслу, второй по словам. Кто выше в обоих, тот выше в общем списке.

## Вход и выход

`upsert_chunks` записывает куски в каталог `CHROMA_PATH`. `search_chunks(query, limit=4, document_names=None)` возвращает не больше `limit` кусков из этого каталога и реестр баз не читает. Другая база открывается отдельно и только после допуска. `document_names` ограничивает поиск уже выбранными файлами. Пустой список и `None` означают весь индекс: третьим аргументом `None` не передаётся, иначе поиск может решить, что подходящих файлов нет.

`reset()` закрывает все открытые каталоги процесса. Следующее открытие снова поднимает клиент, в том числе после смены `store.CHROMA`.

`chunks_for_document` отдаёт куски одного файла по порядку. Так ответ добирает латинское слово, если его нет в первых результатах.

## Что нельзя сломать

- Имя записи — `имя файла`, контрольная сумма текста и номер куска. Два разных файла с одним текстом не должны схлопнуться в одну запись: хранилище оставляет первую и молча игнорирует вторую.
- Запись, удаление и поиск держат один замок. Поиск запоминает индекс на время запроса. Удаление документа во время этого поиска не должно ронять запрос.
- Сужение по имени файла включается, только если хотя бы два слова запроса совпали с именами и их пересечение непустое. Одно слово, например «задания», не привязывает поиск к одному файлу. Совпадение кода внутри текста файла остаётся отдельным путём.
- Пустые значения фильтра `where` не должны выкидывать чужие документы.
- Соседние строки одной таблицы собираются в один кусок в пределах длины, а не в несколько независимых попаданий.
- Подмена последнего слота файлом с редким словом убрана. На 81 вопросе она не меняла место нужного текста, см. раздел ниже.
- Запрос к индексу в поиске по смыслу ждёт не дольше `timeouts.chroma_ms`. Загрузка числовой модели в этот предел не входит. Поток с запросом после предела не обрывается. Повтора этого запроса нет.

## Удалённые эвристики

### `_inject_rare` (Wave 4 #128)

Раньше, если слово вопроса встречалось в одном-двух файлах, `_inject_rare` заменял последний слот четвёрки куском из такого файла. Первый слот при этом не сдвигался.

Прогон на 81 вопросе из `tests/eval/questions.json`, коммит `b5d5206`:

- `--disable inject_rare` не сдвинул `search_hit1_dev`, `search_mrr_dev`, `search_hit4_dev`, `search_hit1_holdout`, `search_mrr_holdout`, `search_hit4_holdout`, `search_retrieval_recall`, `search_fusion_recall_at_4`.
- `best_rank` не изменился ни у одного из 81 вопроса.

Удалены `_inject_rare`, `_rare_docs`, `ContextVar("store_row_features")` и ключ `inject_rare` в `config/runtime.json`. На этих 81 вопросах функция вызывалась каждый раз и ни разу не меняла слоты.

## Оставленные эвристики

### `_focus` (Wave 4 #129, закрыт как wontfix)

`_focus` убирает из запроса для поиска по смыслу токены, которые `_names` счёл именем: две и больше заглавных, буква вместе с цифрой, либо номер вида `19.301-79`. Это происходит только если `scope` уже сузил файлы. Если после удаления остаётся меньше двух слов длиннее 3 букв, запрос остаётся как был.

Почему функция оставлена:

- `--disable focus` на текущем main: `search_hit1_dev` 32/46 → 27/46, `search_hit1_holdout` 27/35 → 24/35. На dev первое место теряют 8 вопросов и получают 3. Снятие `СПА`, `ИМПУС`, `ГОСТ` и номера стандарта как раз держит эти 8 на месте 1: имена встречаются по всему файлу и без снятия поднимают общий кусок.
- Spike со вторым запросом по исходному тексту и RRF с весами 2 и 1: dev 32/46 → 34/46, holdout 27/35 → 26/35, около +40 мс на второй запрос к числовой модели. Плюс на dev при минусе на holdout не берём.
- Вариант «не удалять токен, если он есть в карточке ответа» дал dev 33/46 и holdout 29/35 без второго запроса. `search_chunks` карточки ответа не видит, поэтому в код это не переносилось.

Не удалять `_focus` без такого же прогона с выключенным флагом.

### `scope` (Wave 4 #130, закрыт как wontfix)

`scope` сужает поиск до файлов, где нашлись имена из `_names` (заглавные имена систем, номер стандарта) или хотя бы два слова длиннее 4 букв, чья основа есть в имени файла и не во всех файлах. Если ничего не нашлось, поиск идёт по всему индексу. Пустой список файлов заодно выключает `_focus`: урезать запрос тогда не к чему.

Почему функция оставлена:

- На 24 вопросах, где первое место прыгает при выключении, `allowed` совпал с файлом из карточки. Все 24 сузились через `_names`. Порог «два слова» не сработал ни разу.
- `--disable scope` на текущем main: `search_hit1_dev` 32/46 → 25/46, `search_hit4_dev` 46/46 → 37/46, `search_hit1_holdout` 27/35 → 22/35.
- Пять из шести вопросов, которые при выключении получают первое место, — те же, что и при выключенном `_focus`. Пустой список файлов возвращает в dense исходный запрос. Это разобрано в #129.
- Общие имена файлов, карточка с `"*"` и сдвиг порога «два слова» на этих 24 ни на что не опираются: в списке конкретные файлы, `"*"` нет, порог не участвует.

Не удалять `scope` без такого же прогона с выключенным флагом.
