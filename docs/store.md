# Индекс и поиск

Код: [src/store.py](../src/store.py). Вызов из пайплайна: `search_agent` в [src/agents.py](../src/agents.py).

Хранит чанки в Chroma и ищет по ним. Плотный поиск и лексический BM25 склеиваются через RRF.

## Вход и выход

`upsert_chunks` пишет чанки. `search_chunks(query, limit=4, document_names=None)` возвращает до `limit` чанков. `document_names` ограничивает поиск уже выбранными файлами. Пустой список и `None` означают весь индекс: третьим аргументом `None` не передаётся.

`chunks_for_document` отдаёт чанки одного файла по порядку `chunk_index`. Это путь, которым ответ добирает латинский токен, если его нет в верхней четвёрке.

## Инварианты

- Идентификатор чанка — `имя файла:checksum:chunk_index`. Checksum считает текст. Два разных файла с одним текстом не должны делить один id: Chroma оставляет первую запись и молча игнорирует вторую.
- Запись, удаление и поиск держат один замок. Поиск запоминает объект индекса на время запроса. Очистка глобального индекса загрузкой или удалением не должна ронять уже идущий поиск.
- Сужение по имени файла включается, только если хотя бы две основы запроса попадают в имена и их пересечение непустое. Одна основа («задания») не привязывает поиск к одному файлу. Совпадение кода в тексте файла (отдельный путь по маркерам) остаётся.
- Фильтр `where` из маршрутизации не должен выкидывать чужую коллекцию, если значения пустые.
- Соседние строки одной таблицы собираются в один контекст в пределах бюджета, а не в несколько независимых попаданий.

## Настройки

`config/runtime.json`: `candidates`, `context`, `rrf`, `search_limit`. Каталог Chroma — `CHROMA_PATH`, модель эмбеддингов — `EMBED_PATH`.
