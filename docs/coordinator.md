# Сборка вопроса

Код: [src/coordinator.py](../src/coordinator.py).

Собирает один вопрос в ответ. Либо сразу список имён файлов, либо цепочку шагов.

## Вход и выход

`run(query, dialog_id)` возвращает текст, статус, имена документов и источники. Статусы: «подтверждён», «не подтверждён», «нет ответа».

Память диалога читается через `dialog.get_dialog` и дописывается через `dialog.add_turn`. На диск это сохраняет страница, не этот модуль.

## Цепочка

`select → clarify → search → answer → check`. Из проверки три выхода:

- снова писать ответ, если отзыв не просит другие документы;
- снова искать, если отзыв содержит «документ» или «Разных значений»;
- закончить, если статус уже не «не подтверждён» или попытки кончились.

Потолок попыток — `attempts` в `config/runtime.json`. Сейчас это 2.

## Что нельзя сломать

- Список файлов только для трёх формулировок: «загружен… в систему», «перечисли название», «могу задавать». Сказуемое только в форме «загружен», «загружена», «загружено» или «загружены». «Загруженном в систему» идёт в поиск. «Который загружен» тоже идёт в поиск, если перед ним есть слово не из `catalog_skip`. «Давление в системе» и «загружен в память» идут в поиск.
- Слова самого вопроса из `catalog_skip`, такие как «документы» и «систему», не выкидывают файлы из списка. Остальные слова сравниваются со словами имени, не с куском внутри слова. Слово вопроса может начинаться со слова имени. Если пересечение пустое, возвращаются все имена.
- Для вопроса «сколько» неподтверждённый ответ не заменяется отказом, если в найденном тексте уже есть полная строка обзора таблицы. Иначе человек видит «В документах нет ответа.», а источники очищаются.
- Ссылка `[n]` без оставшегося источника снимается до записи хода. Группа `[1, 2]` разбирается на отдельные номера. Повторный номер в хвосте убирается раньше, ещё в ответе.
