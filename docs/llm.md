# Модель

Код: [src/llm.py](../src/llm.py).

Один процесс пишет ответ и считает длину текста. Числовую модель для поиска грузит индекс, не этот модуль.

## Реестр моделей

Карточки чат-моделей — [config/models.json](../config/models.json), читает их [src/model_registry.py](../src/model_registry.py). Четыре модели: Qwen2.5-1.5B, Qwen2.5-7B (два шарда), QVikhr-3-1.7B-noreasoning и RusMind-Momentum-4.7. У каждой — id, файлы, размер, SHA-256, описание, плюсы/минусы, ресурсы, лицензия, источник. Дефолт — `qvikhr`.

Реестр сканирует `data/models/*.gguf`, группирует шарды `-00001-of-00002`, для неизвестного GGUF строит fallback-карточку. Каталоги эмбеддингов/реранкеров игнорируются; `../` и symlink отклоняются. Отсутствующий файл даёт `available=false`, а не исчезновение карточки.

## Внешние модели (API)

Wave 11. Помимо локальных GGUF можно отвечать внешней площадкой с OpenAI-совместимым
API (по умолчанию Hyperbolic AI, `base_url` https://api.hyperbolic.xyz/v1). Площадка
настраиваемая: каталог — `config/providers.json` (из запросов только читается), операторский
выбор (`provider_id`, свой `base_url`, id модели) — в `data/ui/model.json`, ключ — в
`data/secrets/llm_api_key` (непустая `LLM_API_KEY` окружения важнее файла, пустая строка не
считается ключом).

- Ключ вводится через UI один раз и подхватывается при старте; в GitHub не попадает
  (`data/secrets/` в `.gitignore`). `GET /admin/provider` отдаёт только признак и источник.
- Сбой площадки — явная ошибка в чате (`status` «ошибка модели»), без автофолбэка на локальную
  модель: пользователь сам решает.
- Токены внешних вызовов пишутся в журнал (событие `query`) и в сводку `GET /admin/provider/usage`.
- Контекст 131K ≠ длинный поиск: бюджет промпта (`prompt_tokens=1500`) не меняется; смена этого
  порога меняет ответы и требует scorecard.
- У reasoning-моделей (DeepSeek-R1) свой потолок ответа и температура в каталоге; рассуждение
  чистится `_strip_thinking`; `finish_reason=length` после очистки — «лимит съеден рассуждением»,
  не «пустой ответ».

## Скачивание моделей

[scripts/fetch_models.py](../scripts/fetch_models.py) качает GGUF с Hugging Face: резюм через `Range` во временный `<name>.gguf.part`, затем проверка размера и SHA-256 и атомарное переименование. Режимы: `--check` (только проверка), `--model ID` (конкретная модель), `--force` (перекачать). Перед скачиванием проверяется свободное место. Бинарники в git не идут.

```text
python scripts/fetch_models.py --check
python scripts/fetch_models.py --model qvikhr
python scripts/fetch_models.py --model rusmind --force
```

Повторный запуск уже корректные файлы не качает; битый `.part` не переименовывается.

## Смоук загрузки

`tests/test_models_smoke.py` (маркер `slow`) грузит каждую модель в отдельном процессе и гоняет реальный `llm.complete(...)` + `llm.count_tokens(...)` — то есть проверяет и chat-template. QVikhr использует шаблон noreasoning (`/no_think`), RusMind — Gemma4 (llama-cpp-python==0.3.36). Замерено 05.11 (CPU, тёплый кэш):

- QVikhr-3-1.7B-noreasoning: загрузка 2.87 с, ответ 3.08 с (43 токена).
- RusMind-Momentum-4.7 (gemma4): загрузка 5.06 с, ответ 3.91 с (34 токена).

Обе модели загружаются и отвечают; Gemma4 работает на llama-cpp-python==0.3.36.

## Вход и выход

`complete(system, user, max_tokens=None, examples=(), *, usage_sink=None, timeout_s=None)` собирает разговор: установка, пары примеров, затем вопрос. Возвращает обрезанный текст ответа. `count_tokens` нужен, чтобы вопрос уместился в лимит.

Ответ считается в соседнем потоке. Дольше `timeouts.llm_ms` вызывающий не ждёт и получает `TimeoutError`. При `retries` = 1 вызов повторяется один раз. Поток, который уже считает, не останавливается: модель дописывает ответ без слушателя. Замок на модель при этом занят, пока тот вызов не кончится.

Путь к файлу модели при старте выбирается по приоритету: выбранная модель из `data/ui/model.json` → переменная `LLM_MODEL_PATH` → модель по умолчанию из реестра (`qvikhr`). Выбор пишется атомарно в `data/ui/model.json` (в Docker `data/models` смонтирован `:ro`, поэтому выбор хранится в `data/ui/`, а не в `data/models`). `start.ps1` по умолчанию ставит QVikhr и скачивает его при отсутствии на хосте, `start.ps1 big` — 7B (первый шард). `start.sh`, `Dockerfile` и `docker-compose.yml` по умолчанию тоже указывают QVikhr.

## Что нельзя сломать

- Видеокарта не используется. Это сборка на процессоре.
- Длина контекста по умолчанию 4096, температура 0, потолок ответа 200 токенов. Значения читаются из `config/runtime.json` при каждом вызове, но смена файла на уже загруженном процессе не пересоздаёт модель.
- Загрузка и ответ под замками. Два запроса не зовут модель одновременно.
- Локальная модель создаётся при первом `complete` или `count_tokens`. Для внешней модели `count_tokens` GGUF не открывает (оценка `len//2` или `chars_per_token` из каталога). Тесты, которым файл не нужен, не должны требовать загрузку.

## Проверка

`tests/test_llm.py` проверяет параметры вызова без настоящего ответа. Качество текста — отдельный прогон с моделью 1.5B, в быстрый набор он не входит. Имя проверки: `answer`.
