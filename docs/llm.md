# Модель

Код: [src/llm.py](../src/llm.py).

Один процесс `llama-cpp`. Ответ и подсчёт токенов идут через неё. Эмбеддинги здесь не считаются: их грузит индекс.

## Вход и выход

`complete(system, user, max_tokens=None, examples=())` собирает чат: система, пары примеров, затем пользователь. Возвращает обрезанный текст ответа. `count_tokens` нужен проверке длины промпта.

Путь к GGUF — переменная `LLM_MODEL_PATH`. Её ставит `start.ps1`. По умолчанию это Qwen2.5-1.5B. `start.ps1 big` подставляет 7B. Файл 7B не удалять, даже если ответы снимаются на 1.5B.

## Инварианты

- `n_gpu_layers` равен 0. Это CPU-сборка.
- Контекст по умолчанию 4096, температура 0, потолок ответа 200 токенов. Значения читаются из `config/runtime.json` при каждом вызове, но смена файла на уже загруженном процессе не пересоздаёт модель.
- Загрузка и генерация под замками. Два запроса не зовут llama одновременно.
- Модель создаётся лениво, при первом `complete` или `count_tokens`. Тесты, которым файл не нужен, не должны требовать загрузку.

## Проверка

`tests/test_llm.py` проверяет параметры вызова без настоящей генерации. Качество ответа — узел scorecard `answer`, он не входит в `--nodes fast`.
