> **Аудитория:** DevOps, интеграторы, сопровождающие.
> **Связанные документы:** [Обзор](00-overview.md) · [Архитектура](01-architecture.md) · [Data Science Deep Dive](02-data-science-deep-dive.md)

## 1. Требования

| Компонент | Требование |
|---|---|
| ОС | Windows (PowerShell), Linux/macOS — через Python или Docker |
| GPU | не требуется |
| Сеть | не требуется после установки |
| Docker | Docker Desktop / Docker Engine + Docker Compose |

Модели (не входят в образ, монтируются volume):
- `multilingual-e5-small/` (~2.1 GB);
- `qwen2.5-1.5b-instruct-q4_k_m.gguf` (~1.0 GB).

Документы — в `data/inbox/` (`.txt`, `.md`, `.doc`, `.docx`, `.pdf`, `.xlsx`).

## 2. Запуск

### 2.1 PowerShell

```powershell
.\start.ps1            # 1.5B, http://127.0.0.1:8000
.\start.ps1 restart    # остановить процесс на порту 8000 и запустить снова
.\start.ps1 big        # модель 7B, если файл уже в data/models
```

### 2.2 CLI

```powershell
$env:PYTHONPATH = "src"
$env:CLI_PASSWORD = "пароль"
python -m cli --user ИМЯ ingest --kb ИД data/inbox
python -m cli --user ИМЯ сколько насосов в цехе
```

Без `--user` команда отказывает. Пароль — в `CLI_PASSWORD`, не печатается.

### 2.3 Docker

```bash
docker compose up --build -d
```

Первая сборка — 10–20 минут (torch, sentence-transformers, llama-cpp-python).

Проверка готовности:

```bash
curl http://localhost:8000/ready
```

`{"ready": true}` и код 200 — модель и индекс готовы. Код 503 с `elapsed_sec` и `eta_sec` — ещё грузится. Первый прогрев может занять больше пяти минут. Страница — `http://localhost:8000`.

## 4. Конфигурация

В `config/`: лимиты, когда отвечать списком файлов, словарь проверки чисел. В `data/prompts/`: текст, который видит модель, и примеры.

Принцип: то, что зависит от конкретных документов, живёт в `config/` и `data/prompts/`, а не в `src/`. В `src/` не должно быть имён файлов и фактов из документов.

## 5. Мониторинг и состояние

### 5.1 `/ready`
Эндпоинт готовности API: проверяет, что сервис поднялся и модели загружены.

### 5.2 `data/ui/workspace.json`
Хранит диалоги, оценки 1–5 и дерево папок. Список диалогов берётся из сохранённого файла. Дерево документов обновляется, когда `/ready` отвечает 200. Пока индекс строится, страница открывается сразу.

### 5.3 Что отслеживать
- долю отказов («В документах нет ответа»);
- долю успешных переписываний;
- латентность.

## 6. Аудит

`data/audit/` — журнал. Детали — в [audit.md](audit.md) (если есть в репозитории) или в существующих документах.

## 7. Известные ограничения

- **Один процесс / один пользователь.** Многопользовательский режим не заявлен.
- **Нет стриминга.**
- **CPU-only.** 7B на слабых машинах может быть неприемлемо медленной.
- **Локальный Chroma.** Не рассчитан на огромные корпуса и распределённую нагрузку.
- **Качество зависит от документов.** Система отказывает, если ответа нет в корпусе — by design.

## 8. Что нельзя ломать

- Не записывать в `src/` имена файлов и факты из них.
- Не опускать нижнюю границу в `tests/eval/floors.json` и не передавать `--write-floors` / `--raise-floors`, пока об этом не попросили и проверка не написала, что порог пройден.
- `tests/eval/last.json` и `pytest tests/test_floors.py` качество заново не меряют: они сравнивают уже записанные числа.
- После правки `src/`, `config/` или `data/prompts/` заново измерить то, что сдвинулось. Как именно — в [eval.md](eval.md).

## 9. Roadmap

1. **Реранкер** поверх гибридного поиска.
2. **Стриминг ответа.**
3. **Умный чанкинг таблиц.**
4. **Кэширование** эмбеддингов запросов и результатов поиска.
5. **Офлайн-бенчмарк** — фиксированный набор вопросов и метрик для сравнения конфигураций (частично уже есть в `tests/eval/`).
